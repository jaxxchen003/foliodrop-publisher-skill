# Visual Quality Rules

Use these rules when generating or adapting visual HTML for FolioDrop.

## General

- Make the first viewport immediately communicate what the artifact is.
- Use real structure, not decorative filler.
- Keep type hierarchy tight: display heading, section heading, body, caption.
- Avoid one-note palettes. Pair a neutral base with one or two accents.
- Avoid generic gradients, decorative blobs, and oversized cards.
- Use stable responsive dimensions for decks, grids, tiles, and media frames.
- Ensure all text fits on mobile and desktop.
- Keep CTAs specific: "View work", "Book review", "Reply with feedback", "Join waitlist".

## HTML Presentation Deck

- Maintain 16:9 composition.
- Use one idea per slide.
- Add slide numbers and a clear progression.
- Prefer strong editorial layouts over bullet dumps.
- Include speaker notes only as hidden comments if needed.

## Resume

- Put name, role, location or availability, and contact methods near the top.
- Lead with evidence: outcomes, numbers, recognizable domains, shipped work.
- Keep the layout printable.
- Avoid personality-heavy copy unless the user asks.

## Email Campaign Preview

- Keep the message narrow: one audience, one offer, one action.
- Include subject line, preview text, body, CTA, and footer.
- Use table-like or constrained layout that resembles a real email.
- Do not include tracking pixels or remote scripts.

## One-Page

- H1 should be the product, offer, or literal category.
- Show the workflow or value in the first two sections.
- Include proof, limits, pricing or next step when available.
- Make it feel like a page someone can share today.

## Portfolio Case Study

- Lead with project title, role, timeframe, and outcome.
- Show constraints and decisions, not just final screenshots.
- Use artifact blocks with short captions.
- End with results and what changed for users.
